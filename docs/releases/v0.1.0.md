# v0.1.0

**Release Date:** 2026-05-17

Initial release of capability-stack-spec, a Go library and CLI for defining capability stacks with layers, capabilities, and PRISM maturity integration.

## Highlights

- **Go Types & Validation**: Complete type system matching JSON Schema with comprehensive validation including reference integrity and dependency cycle detection
- **CLI Tool**: `capstack` command with validate, init, list, show, and render commands
- **Diagram Rendering**: D2 diagrams (default and executive grid styles) and static HTML output
- **Web Component**: Lit-based `<capability-stack>` element for embedding in websites and MkDocs

## Core Types

| Type | Purpose |
|------|---------|
| `CapabilityStack` | Root document with metadata, layers, categories, capabilities |
| `Capability` | Individual capability with lifecycle status, dependencies, tooling |
| `Layer` | Horizontal band representing phases or stages |
| `Category` | Visual grouping with optional color |
| `Tool` | Tooling information with vendor, type, status |
| `PRISMRef` | Reference to PRISM maturity model for SLI tracking |

## Enum Constants

- **CapabilityStatus**: planned, in-progress, implemented, operational, deprecated
- **Priority**: critical, high, medium, low
- **Domain**: security, ai, platform, data, observability, infrastructure, product, operations
- **Phase**: plan, design, build, test, release, deploy, operate, monitor, respond, recover
- **Framework**: nist-csf-2.0, nist-800-53, iso-27001, soc2, pci-dss, cis, mitre-attack, owasp, slsa, ssdf

## CLI Commands

```bash
# Validate a capability stack document
capstack validate stack.json

# Create a new capability stack
capstack init -d security -o security-stack.json

# List capabilities with filtering
capstack list stack.json --status=implemented --layer=build-test

# Show capability details
capstack show stack.json sast

# Render to D2 diagram
capstack render stack.json -o stack.d2
capstack render stack.json --style=grid -o exec-view.d2

# Render to HTML
capstack render stack.json -f html --standalone -o stack.html
```

## Validation Features

- Required fields: id, name, layerId for capabilities
- Kebab-case ID format enforcement
- Enum value validation for all constants
- Reference integrity (layerId, categoryId must exist)
- Unique ID enforcement across layers, categories, capabilities
- Dependency cycle detection using DFS

## Rendering Options

### D2 Diagram Styles

| Style | Description |
|-------|-------------|
| `default` | Standard view with dependency arrows |
| `grid` | Clean executive view - aligned boxes, no arrows, shadows |

### HTML Options

| Flag | Description |
|------|-------------|
| `--standalone` | Generate complete HTML document |
| `--dark` | Use dark color theme |
| `--no-legend` | Hide status legend |
| `--no-foundational` | Hide foundational capabilities |

## Web Component

```html
<script type="module" src="capability-stack.js"></script>

<capability-stack
  src="stack.json"
  theme="light"
  show-legend
  show-foundational
  interactive>
</capability-stack>
```

Works with MkDocs and Material for MkDocs (unlike React components).
